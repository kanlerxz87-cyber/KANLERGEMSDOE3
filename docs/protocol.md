# Standing project and parallel-run protocol

Read this page and the [README](../README.md) at the start of every session.
The full original user request is the source of authority; this is an operational
record, not a claim to be a verbatim transcript.

- **Maximize P(Win):** prioritize evidence, expected value, responsible resource
  use and challenge compliance over a flashy but unvalidated submission.
- **Own the Outcome:** automatically restore and audit what is available, fix
  defects, record negative results, and do not hide blockers.
- Work in one explicitly assigned method lane; propose 3–5 hypotheses before
  implementing. Stop if any registry surface rank correlation exceeds 0.90 or
  more than 70% of candidate dots lie within 3 px of one registry raster's
  dots. Check pre-placement and final support. Do not redefine the rule.
- Reuse the template cache, evaluator and writer. Hide whole segments with a
  buffer, compute catalogue features from visible faults only, mask visible
  faults pixel-exactly and pool DTI (alpha 0.2, beta 0.8, triangular radius
  300 m). Report the evaluator version, withheld positives and 95% CI with
  each **HOLDOUT-DTI**. A submission is **ORGANIZER-CONFIRMED** only with an
  organizer submission-page receipt associating the score with its bytes.
  Owner-reported values and projections are **not** scores.
- Test each feature alone: oriented AUC > 0.90 means potential leakage; stop and
  audit. At most three experiments or two hours. Negative results count.
- A candidate's run card must include mechanism, named non-fault mimic,
  holdout + CI, registry correlations and overlaps, TIFF SHA-256, validation,
  name, note (≤140 characters) and promote/negative verdict. No leaderboard
  slot is spent here: promotion/slot selection is separate.
- If uniqueness, holdout, input provenance, or format cannot be proven, say
  **DO NOT SUBMIT**. A local validation receipt is not an organizer receipt.
- Use only licensed data shareable with the organizers, cite official sources,
  preserve provenance, and keep raw data and caches out of Git.
- After implementation, conduct three review/verification passes. Request,
  create and merge a pull request only for the user's current session branch;
  report unresolved issues and next steps.
