When a file is actually approved

How to submit

These steps are for a future candidate after the automatic gates and separate selector have passed.

  1. Check the decision banner. Proceed only if the site shows an approved unique file, a same-evaluator holdout win, leakage checks, a saved-byte validator and separate slot selection.
  2. Download the exact approved TIFF. Keep the filename and SHA-256 from the run card. A renamed old TIFF is not a unique submission.
  3. Open the competition submission page. Sign in to DrivenData, choose Submit → Make new submission, and upload the one TIFF or its single-TIFF ZIP.
  4. Use the provided short note. Copy the candidate’s name and note (≤140 characters) when available. Check the portal’s current submission allowance.
  5. Preserve the official receipt. Keep the portal result and local file hash together. A leaderboard position alone does not identify the file.

Format safety

Avoid the [0, 1] error

The local inspection checks the actual TIFF bytes: one float32 band, grid match, finite values in [0,1], and no NaN or masked cells within the footprint. It rejects out-of-range sentinels instead of clipping them.

The shared writer’s all-finite exterior is a conservative local policy; the official problem description permits null/NaN outside the bounds. We cannot infer the cause of the earlier portal error without the failed file or guarantee how the portal handles exterior values.
