Submission guide

From evidence to an eligible file.

A practical checklist for a future authorized run. This page does not upload, select or reserve a competition slot.

Step 01

Resolve the stop, without inventing exemptions

The method lane is not specified, and a verified positive-everywhere prior causes 100% overlap. A single prior is sufficient to reject but cannot prove registry completeness. Do not continue placement unless the protocol owner explicitly clarifies the applicable policy and lane. Preserve the old audit and regenerate evidence after any authorized change.

Step 02

Reproduce the evidence and scientific gates

python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/restore_assets.py --focus --features --external
.venv/bin/python scripts/audit_evidence.py

Run from the repository root with GitHub CLI installed. Restoration downloads public owner mirrors into an ignored cache; hashes establish integrity, not organizer authentication. If access or a hash check fails, stop. Follow official data-use rules separately.

  1. Hide whole fault segments with a buffer, rebuild every catalogue-based feature from visible faults only, and mask visible faults pixel-exactly.
  2. Test each feature alone. AUC above 0.90 is a leakage alarm until disproved.
  3. Use the unchanged shared evaluator: pooled HOLDOUT-DTI with α=.2, β=.8 and a 300 m triangular kernel. Record evaluator version, withheld-positive count, 95% spatial confidence interval, and paired comparison with the same-fold incumbent.
  4. Check every applicable registry raster both before placement and on the final dots. Stop if rank correlation is >.90 or directed overlap within 3 pixels is >70%; missing registry data is not a pass.
Step 03

Validate the actual saved GeoTIFF

Use the verified shared submission writer; do not rename or perturb an old file. The official task calls for one float32 probability band, values [0,1], EPSG:32611, and the exact 100 m reference grid. The official page specifies null/NaN outside bounds; the shared project's all-finite local policy is a separate assumption about saved pixels, and a local pass is not portal acceptance.

.venv/bin/python scripts/check_submission.py path/to/candidate.tif --surface path/to/surface.tif --out evidence/preflight.json

The preflight compares the supplied bytes against the shared local validators and the single witness. It intentionally returns nonzero and ok_to_submit: false; it cannot establish full-registry clearance, holdout quality, official acceptance, or selector approval. It never repairs or uploads a file. A range error must be investigated from the saved bytes, not hidden by clipping.

Step 04

Only after separate selector approval

Confirm current competition rules and rolling weekly cap on the DrivenData competition page. A separate selector must authorize an eligible, validated exact file. Navigate to the submission page, choose that file, and use the selector-approved concise name and note of at most 140 characters. Save the submitted SHA-256 and organizer receipt. Do not infer a leaderboard score from a holdout; no slot has been spent by this project.
