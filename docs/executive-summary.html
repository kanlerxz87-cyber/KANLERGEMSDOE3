1. Earn eligibility automatically

  1. Declare a single lane and reuse the shared stack. Freeze the method and its non-fault mimic. Respect the cap of three experiments or two hours.
  2. Run leakage canaries. Each feature must be tested alone; AUC above 0.90 is treated as leakage until resolved.
  3. Run the matched holdout. Withhold buffered whole segments, calculate catalogue features from visible faults only, mask visible faults pixel-exactly and report pooled HOLDOUT-DTI with evaluator, withheld positives and spatial-block 95% CI. The candidate must beat the current same-evaluator best with a positive paired interval.
  4. Check novelty before and after placement. Compare full-footprint rank correlation and directional within-three-pixel dot overlap against every current registry raster. Stop on correlation above 0.90 or overlap above 70%. Record missing or incompatible references; do not silently exempt the lattice.
  5. Validate the exact saved bytes. Reopen the single-band float32 GeoTIFF and check CRS, shape, transform, finite in-footprint values, [0,1] range, nodata behavior and SHA-256 against the authenticated template. The note must be at most 140 characters.
  6. Hand evidence to a separate selector. The evaluation step does not choose a weekly slot. Check the current competition page and quota; a local gate does not guarantee portal acceptance.

Run python scripts/readiness.py to see the current fail-closed evidence checklist. It never picks or uploads a submission.

2. Understand the TIFF requirements

The official problem page specifies one float32 layer, EPSG:32611, 100 m resolution, matching bounds and confidence values between 0 and 1. It says outside bounds should be null or NaN. The submission form also requires the sample's exact shape and geotransform.

Range error: The previously reported “Predicted values must be in range [0, 1]” error does not establish its cause. Inspect for sentinel values, infinities and NaNs within the footprint and validate the exact saved file. An all-finite zero-outside file passes a whole-array numeric check, but conflicts with a literal reading of the written outside-footprint guidance; portal acceptance of either encoding is not established by this project.

The restored sample is an owner mirror, not an authenticated organizer download. It contains known-fault positives despite the official description of a zero-prediction sample. Use it as a provisional grid reference only; independently authenticate it against the organizer's sample before final selection.

3. If a future file is separately approved

  1. Open the GEMS competition, sign in and go to New submission.
  2. Choose the exact approved .tif or a ZIP containing that one TIFF. Confirm its SHA against the automated receipt and never rename a previous file as a new method.
  3. Paste the approved unique name/note shown with that file. The note is optional on the form; this project's protocol limits it to 140 characters.
  4. Check the current weekly quota and select the file only after the separate selector approves it. The official rules PDF describes three submissions per week; the live page controls current conditions.
  5. Submit, then preserve the organizer's submission-page receipt. A local holdout is not an organizer-confirmed score. The same chosen final submission is used across the two prize rounds.

Prize finalists must deliver reproducible solution assets, and the official rules require disclosure of generative-AI use in the narrative if applicable. See the full rules for eligibility and documentation.
