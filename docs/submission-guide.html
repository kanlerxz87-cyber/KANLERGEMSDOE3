How a future approved submission works

  1. Require an explicit “OK TO SUBMIT” verdict.

    The exact file must pass saved-byte validation, complete uniqueness checks, leakage canaries and a clean same-evaluator holdout improvement gate. A separate selector must approve a real slot with current authenticated capacity. This run does not pass.

  2. Download the prediction TIFF or single-TIFF ZIP.

    Use the download attached to the approved run card, not an old peer copy and not this page. Verify its SHA-256 against the published receipt. The zero-filled version prevents NaN/sentinel issues in generic full-grid range checks; the NaN-outside twin follows the sample’s missing-data convention. Neither has an organizer acceptance receipt here.

  3. Open the official submission form.

    At DrivenData → New submission, choose the approved .tif or its single-TIFF .zip. Use the exact short name and note from that run card. The name identifies an experiment; it does not make duplicate pixels unique.

  4. Preserve the organizer receipt.

    Link the submission ID, file hash, returned score and receipt before calling a result ORGANIZER-CONFIRMED. Public leaderboard observations alone do not establish a particular artifact’s score. Initial/final private-test selection remains separate.
